# STM32 入门培训教材

## 基础篇

### 第 6 章 串口发送：给单片机装一双眼睛

#### 6.1 本章目标

前面的实验中，你可以通过 LED 判断输出引脚有没有变化。但如果想知道“循环执行了多少次”“某个变量现在是多少”，只看 LED 就不够了。

你可以把单片机想象成一个埋头工作的同学。LED 能告诉你“他有动作”，串口则能让他把“我现在做到哪一步、算出了什么结果”说给电脑听。本章就给代码增加一个能输出文字的窗口。

学完这一章，你能：

1. 用一根 USB 线把开发板和电脑连接起来，知道这一根线同时完成供电、下载和串口通信。
2. 在设备管理器中找到板载 ST-Link 虚拟串口的 COM 端口，并设置 VOFA+ 串口助手。
3. 通过 USART1 发送字符、字符串和整数。
4. 使用 `Serial_Printf` 输出变量，辅助排查代码。

本章先完成开发板向电脑发送信息。电脑发送指令、开发板接收数据的内容，放在提高篇提 4。

#### 6.3 硬件连接

##### 6.3.1 一根 USB 线完成三件事

这次实验涉及三个任务：把代码写进单片机、给开发板供电、把运行信息传到电脑。你可以把它们想成“交任务书”“提供工作所需的电源”和“汇报工作进度”。

使用社团开发板时，这三件事都由**同一根 USB 线**完成，不需要外接下载器、USB 转串口模块或杜邦线：

| 任务 | 信号在板上的路径 | 作用 |
|---|---|---|
| 下载代码 | 电脑 → USB → 板载 ST-Link → SWD（板上走线）→ 单片机 | 将编译后的代码写入单片机 |
| 串口通信 | 单片机 PA9/PA10 → 板载 ST-Link 虚拟串口 → USB → 电脑 | 把运行时输出传给串口助手 |
| 开发板供电 | 电脑 USB 5V → 板载稳压电路 → 单片机 | 让单片机运行 |

也就是说，第 2 章用来下载程序的那根 USB 线，在本章同时充当串口线。**电脑上打开的 COM 端口，就是板载 ST-Link 提供的虚拟串口。**

##### 6.3.2 板载 ST-Link 为什么还能当串口

电脑的 USB 接口和单片机的串口引脚使用不同的通信方式，二者不能直接对话。

开发板上除了主单片机，还有一颗板载 ST-Link 芯片，它就像一名“翻译”：靠近电脑的一侧使用 USB，靠近单片机的一侧在板内同时连着 SWD 引脚（负责下载）和串口引脚（负责收发信息）。它把单片机串口发来的 TTL 电平信号，打包成 USB 信号交给电脑。这一功能称为 **ST-Link 虚拟串口（VCP，Virtual COM Port）**。在电脑看来，它和一个真实的串口设备没有区别。

本章数据经过的顺序是：**单片机 USART1 → PA9（TX）→ 板上走线 → 板载 ST-Link 虚拟串口 → USB → 电脑驱动 → 串口助手。**

这条路径在出厂时已经在板上连通，你不需要接任何一根杜邦线。

##### 6.3.3 找到板上 TXD、RXD 的位置

串口使用的是 USART1 的两个固定引脚：

- **PA9：USART1_TX（发送）**，单片机从这里把数据发出去；
- **PA10：USART1_RX（接收）**，数据从这里进入单片机。

在板载调试排针（丝印 H2）上，这两个信号分别标为 **TXD** 和 **RXD**，与 SWD 用的 SWCLK、SWDIO 以及电源、地排在同一组排针上，如下图所示。

![图 6-1 板载串口 TXD、RXD 在开发板上的实际位置（红圈处），USB 口位于开发板右上角](assets/ch06-01-串口TXD-RXD实物位置.png)

![图 6-2 调试排针 H2 的 PCB 位置图：TXD、RXD 对应 PA9、PA10，SWCLK、SWDIO 为 SWD 下载信号](assets/ch06-02-调试排针PCB位置.png)

这些信号在板上已经与 ST-Link 连通，排针主要用于观察和测量，**保持出厂状态即可，不需要插跳线帽或杜邦线**。你要做的硬件操作只有一个：用一根支持数据传输的 USB 线把开发板的 USB 口和电脑连起来。

**TX 是 transmit（发送），RX 是 receive（接收），名称都以设备自身为主体。**你可以把 TX 想成嘴巴，RX 想成耳朵：一个设备用嘴巴说话，另一个设备用耳朵听。板载 ST-Link 与单片机之间已经按“单片机 TX 接 ST-Link 的 RX、单片机 RX 接 ST-Link 的 TX”交叉连好，这也是以后你外接其他串口模块时要遵循的方向。

**PA10 虽然在板上已经连好，但本章代码只打开发送。**物理连接一直存在，是否使用接收方向由软件决定；本章初始化时只开启发送模式，等提高篇提 4 再开启接收。

##### 6.3.4 找到虚拟串口的 COM 端口

ST-Link 的驱动在第 2 章已经安装。USB 连接正常时，板载 ST-Link 在设备管理器中会同时提供两类设备：一个用于下载调试的 ST-Link 设备，和一个用于串口通信的虚拟串口。

按以下顺序确认 COM 端口：

1. 用 USB 线把开发板连接到电脑，等待系统识别。
2. 右键 Windows 开始按钮，打开“设备管理器”，展开“端口（COM 和 LPT）”。
3. 找到新增的串口设备，名称通常类似 `STMicroelectronics STLink Virtual COM Port (COM5)`，如图 6-3；部分固件或系统下显示为 `USB 串行设备 (COM5)`。记录括号里的 COM 端口号，名称和编号以本机实际显示为准。
4. 如果电脑接着多个串口设备，可拔下开发板的 USB 线看哪个端口消失，再插回确认——这是最可靠的辨认方法。

COM 端口号像电脑给设备安排的“窗口编号”。串口助手必须找到正确窗口，数据才会显示。换 USB 接口后编号可能变化，不能照抄示例中的 `COM5`。

如果“端口”分类下没有任何新增设备，按顺序排查：

- 换一根确认能传数据的 USB 线（只能充电的线没有数据脚），并换一个 USB 接口重试；
- 回到第 2 章检查 ST-Link 驱动是否安装成功，设备管理器里是否还能看到 ST-Link 调试设备；
- 如果能正常下载程序、却始终看不到虚拟串口，说明 ST-Link 固件可能未开启虚拟串口功能，联系社团负责人处理，不要自行刷写固件。

![图 6-3 设备管理器中的板载 ST-Link 虚拟串口：STMicroelectronics STLink Virtual COM Port (COM5)，括号中的编号以本机为准](assets/ch06-03-虚拟串口端口.png)

##### 6.3.5 下载并认识 VOFA+ 串口助手

串口助手是电脑上用来查看串口数据的软件。社团统一使用 **VOFA+（读作“伏特加”）**：它在 Windows 上对个人使用免费，既能当普通串口助手逐行显示文字，也能把数据画成实时波形，后续 ADC、电机等章节会用到波形功能。

**下载与安装**（只从官网下载，不要从第三方下载站下载）：

- 官网首页：[https://www.vofa.plus/](https://www.vofa.plus/)
- 下载中心：[https://www.vofa.plus/downloads/](https://www.vofa.plus/downloads/?index=0)
- Windows 电脑选择 **64 位**版本；也提供免安装版，解压后直接运行 `VOFA+.exe` 即可，功能与安装版相同。

打开软件后，界面各区域如图 6-4 所示：左侧是“协议与连接”设置面板，下方是收发数据的控制台，中间大块区域是波形／控件区（本章留空即可，不用添加任何控件）。

![图 6-4 VOFA+ 界面总览：① 协议与连接面板；② 波形／控件区（本章不用）；③ 数据接收控制台；④ 数据发送区。图中 COM 号和参数仅为示例](assets/ch06-04-VOFA界面总览.png)

**连接串口只需四步**（对应图 6-5）：

1. 点击左上角的圆形按钮，展开“协议与连接”面板。
2. **协议引擎**选 `RawData`：原始数据模式，收到什么就原样显示什么，不做任何解析，正好当普通串口助手用。另外两种 `FireWater`、`JustFloat` 是画波形时解析数字用的，后面章节再学。
3. **数据接口**选 `串口`；在“串口参数配置”里，端口号选设备管理器里的 `STLink Virtual COM Port`，波特率选 `9600`，数据流控、校验位都选 `None`，数据位数 `8`，停止位数 `1`。
4. 再点一次左上角圆形按钮，按钮变蓝（连接状态）即连接成功。

![图 6-5 连接配置：协议引擎选 RawData、数据接口选串口、端口选 ST-Link 虚拟串口、波特率按本章改为 9600。图中 115200 与 CH340 字样仅为示例](assets/ch06-05-VOFA串口连接配置.png)

**再到下方控制台确认两件事**：

- 工具栏处于 `Abc`（文本）模式，而不是 `Hex`（十六进制）；`Rx` 按钮保持按下，表示显示接收到的数据；右侧编码保持 `UTF-8`。
- 此时按一次开发板复位键，控制台就应逐行滚动显示文字。

#### 6.4 原理说明

**串口像按顺序递送小纸条。**你交给它一段文字，它会按约定把数据逐个发出；本章每个数据字节包含 8 个数据位。USART1 是单片机内部负责这项工作的外设，PA9 是它的发送出口，板载 ST-Link 虚拟串口是把纸条转交给电脑的中间设备。串口助手接收到数据后，再按文本模式解释和显示。

**双方要使用相同的节奏和格式。**可以把波特率想成约定的说话速度：一端说得快，另一端按慢节奏听，就容易听错。本章波特率为 `9600`，并使用 8 个数据位、1 个停止位、无校验、无流控，简称“9600、8N1”。起始位像“我要开始了”的提示，停止位像“这一份说完了”的间隔；本章无需展开波形，按相同参数设置即可。波特率不是每秒显示多少字符，它还要容纳每份数据的起止信息。

**字符和数值不是同一件事。**电脑按编码把字节解释成文字。以常用 ASCII 编码为例，字符 `'1'` 对应十进制 49；数值 `1` 对应的是另一份数据，文本显示时不会自动变成数字符号 `1`。就像“数字一”和“写着一的纸条”是两个层次。要显示变量 `123`，格式化打印会先把它组织成字符 `'1'`、`'2'`、`'3'`，再逐个发送。

**复用输出就是把引脚交给专门的工作人员。**点亮 LED 时，你直接命令引脚变高或变低；发送串口数据时，让 USART1 按节奏控制引脚。PA9 的 `GPIO_Mode_AF_PP` 是“复用推挽输出”，表示将输出控制交给串口外设。你只需记住这次实验的选择，不用一次学习所有 GPIO 模式。

> 想彻底搞懂为什么？见提高篇 提 4：串口接收与中断。

#### 6.5 上手步骤

##### 6.5.1 第一步：放好文件，先看到一条信息

复制一份标准工程作为本章工程。将 6.6 的三个完整文件分别保存到表中位置：`main.c` 替换模板原有入口文件，`Serial.c/.h` 放进 `Hardware`。文件名和后缀要保持一致，工程中只保留一份含 `main` 函数的源文件。`main.c` 是入口，`Serial.c` 是发送功能的实现，`Serial.h` 则像功能清单，告诉其他文件可以调用哪些串口函数。

在 Keil 工程的 `Hardware` 分组中加入 `Serial.c`。头文件位于磁盘上还不够，工程的头文件搜索路径也必须包含 `Hardware`；标准模板通常已配置。

检查模板已有以下标准库源文件：`stm32f10x_rcc.c`、`stm32f10x_gpio.c`、`stm32f10x_usart.c`，并通过 `stm32f10x_conf.h` 启用相应头文件。若缺失，由负责人更新公共模板；本章不要求读者修改 `Library/Start/System`。

打开 `Options for Target → Target`，勾选 `Use MicroLIB`。保留模板的芯片、宏定义、启动文件与下载设置，编译无错误后下载。

用 USB 线连接开发板与电脑，确认设备管理器中能看到板载 ST-Link 虚拟串口的 COM 端口。打开 VOFA+（还没安装的先按 6.3.5 下载），按下表设置并连接，最后按一次开发板复位键。先连接串口再复位，是为了接住启动时只发送一次的欢迎信息。

| VOFA+ 中的设置项 | 本章设置 |
|---|---|
| 协议引擎 | `RawData`（原样显示，不做解析） |
| 数据接口 | `串口` |
| 端口号 | 设备管理器中 `STLink Virtual COM Port` 对应的 COM 端口 |
| 波特率 | 9600 |
| 数据位数／停止位数 | 8／1 |
| 校验位／数据流控 | None／None |
| 接收显示 | 下方控制台选 `Abc`（文本）模式，勾选 `Rx`，编码 `UTF-8` |

你应先看到 `A` 和欢迎信息，随后看到逐行增加的 `count`。成功后，再回来看这些信息是怎样发出去的。

##### 6.5.2 第二步：认识串口初始化

在完整代码中找到 `Serial_Init`。它只做四件事：

1. **打开时钟开关。**GPIOA 和 USART1 都要使用，因此分别使能；先沿用模板主频，不展开时钟配置原理。
2. **配置 PA9。**选择 `GPIO_Mode_AF_PP`，让 USART1 控制发送引脚。`GPIO_Speed_50MHz` 是 GPIO 输出速度档位，不是串口波特率。
3. **设置通信参数。**使用 `USART_InitStructure` 填写波特率、数据位、停止位等。`USART_Mode_Tx` 表示本章只开启发送。
4. **开启 USART1。**完成配置后调用 `USART_Cmd`，串口才能工作。

这里的结构体就是第 3 章讲过的“一组打包配置项”。所有成员都要填写，不能只改波特率而留下其他成员未初始化。可以把初始化想成填写一张完整的任务单：引脚是出口，通信参数是工作规则，开启串口是正式开工。任务单没填全，外设就可能按错误的条件工作。

##### 6.5.3 第三步：从一个字符到一行文字

`Serial_SendByte` 一次发送一个字节。发送前先查看 `USART_FLAG_TXE`：它表示串口是否能接收下一份待发送数据。尚未就绪时，代码在循环中等待；就绪后调用 `USART_SendData`。这像给窗口递纸条：先确认窗口有位置接收，再把下一张递过去；如果上一张还没被取走就直接塞入，可能覆盖尚未处理的数据。

`Serial_SendString` 则从字符串开头逐个取字符，遇到结尾的 `\0` 停止。因此它适合发送文字，不适合直接发送包含零字节的任意二进制数组。`\0` 像字符串末尾的“到此结束”标记，不是需要显示的字符。代码中的 `*text` 取出当前位置的字符，`text++` 则把指针移到下一个字符；这与第 3 章的指针知识对应。

完整示例里的 `Serial_SendByte('A')` 用单引号表示一个字符；`Serial_SendString("Hello, STM32!\r\n")` 用双引号表示字符串。末尾 `\r\n` 表示回车和换行，让下一条信息从新的一行开始。

本章采用等待式发送，容易理解，但打印需要时间。不要在高速循环里无节制输出，也不要把它用于要求立即返回的场合。`TXE` 表示可以继续交付数据，不等于最后一个字符已经全部离开发送引脚；本章持续运行，无需在每个字符后等待整帧发送完成。

##### 6.5.4 第四步：用格式化打印输出变量

`printf` 本身负责把数值组织成文字，并不知道要从哪根引脚输出。我们在 `Serial.c` 中实现 `fputc`，让它把字符交给 `Serial_SendByte`，这就是本章所说的 **printf 重定向**。你可以把 `printf` 看成负责“写好纸条”的人，`fputc` 负责把纸条上的字符一个个交到指定窗口，`Serial_SendByte` 负责交给 USART1 发送。重定向就是为标准输出指定这条路线。

为方便后续章节复用，再提供 `Serial_Printf`。它接收与 `printf` 类似的参数，通过 `vprintf` 共用上述输出路径。你只需会调用，不必现在掌握可变参数的内部实现。执行完整示例中的计数打印时，`count` 若为 12，`%lu` 就被替换成文字 `12`，电脑最终收到 `count=12` 和换行字符。

| 格式 | 作用 | 示例结果 |
|---|---|---|
| `%lu` | 输出 `unsigned long` 类型的十进制整数 | `count=12` |
| `%c` | 输出一个字符 | `A` |
| `%s` | 输出字符串 | `ready` |
| `\r\n` | 回车换行 | 下一次输出另起一行 |

本章计数变量为 `uint32_t`，调用时使用 `(unsigned long)count`，与 `%lu` 明确配对。括号中的类型转换，是明确把数值按 `unsigned long` 类型交给打印函数；格式符像一张取货单，必须和后面的参数类型对应。先照着这组写法使用，避免显示出与实际值不同的结果。

##### 6.5.5 第五步：让串口帮你排查代码

完整示例将 `boot: serial ready` 放在循环之前，将 `count` 放在循环里面。前者正常情况下每次复位输出一次，后者不断输出。看到它们，你就知道代码完成了初始化，并且还在循环运行。

以后排查问题时，可以在可疑函数前后分别输出 `before` 和 `after`。如果前后两次打印间隔很短且等待后仍只出现前者，可以优先检查两条打印之间的执行过程；打印只能提供定位线索，还要结合执行条件判断。它像沿路设置的路标：看到上一块、没看到下一块，就先检查这段路，而不是从头重写代码。打印提示应短而明确，优先使用英文和数字，先排除中文编码带来的干扰。

示例使用 `Delay_ms(1000)` 降低输出频率，约每秒打印一次；发送和其他代码也耗时，因此这不是精密计时实验。

#### 6.6 完整代码

以下文件作为一组使用，基于 6.2 的标准模板；它们不是脱离启动文件和标准库即可独立构建的完整 Keil 工程。模板还需保留原有 `Delay.c/.h`。本章不新增中断服务函数。

##### 6.6.2 `Hardware/Serial.c`

```c
#include "Serial.h"
#include <stdio.h>
#include <stdarg.h>

/**
 * @brief  初始化USART1发送功能，使用PA9输出
 * @param  无
 * @retval 无
 */
void Serial_Init(void)
{
    GPIO_InitTypeDef GPIO_InitStructure;
    USART_InitTypeDef USART_InitStructure;

    /* 引脚和串口是两个外设，使用前都要打开时钟开关。 */
    RCC_APB2PeriphClockCmd(RCC_APB2Periph_GPIOA, ENABLE);
    RCC_APB2PeriphClockCmd(RCC_APB2Periph_USART1, ENABLE);

    GPIO_InitStructure.GPIO_Pin = GPIO_Pin_9;          /* USART1默认发送引脚PA9。 */
    GPIO_InitStructure.GPIO_Speed = GPIO_Speed_50MHz; /* 引脚输出速度档位，并非波特率。 */
    GPIO_InitStructure.GPIO_Mode = GPIO_Mode_AF_PP;   /* 让串口接管引脚的输出。 */
    GPIO_Init(GPIOA, &GPIO_InitStructure);

    USART_InitStructure.USART_BaudRate = 9600;                       /* 与电脑端保持一致。 */
    USART_InitStructure.USART_WordLength = USART_WordLength_8b;       /* 每份数据使用8位。 */
    USART_InitStructure.USART_StopBits = USART_StopBits_1;            /* 使用1位停止位。 */
    USART_InitStructure.USART_Parity = USART_Parity_No;               /* 本实验不使用校验。 */
    USART_InitStructure.USART_HardwareFlowControl = USART_HardwareFlowControl_None; /* 不使用流控线。 */
    USART_InitStructure.USART_Mode = USART_Mode_Tx;                  /* 只发送，不开启接收。 */
    USART_Init(USART1, &USART_InitStructure);

    USART_Cmd(USART1, ENABLE); /* 配置完成后才开启串口。 */
}

/**
 * @brief  等待串口可接收新数据后提交一个字节
 * @param  data：待发送的字节
 * @retval 无；返回时不保证该字节已经全部发送到引脚
 */
void Serial_SendByte(uint8_t data)
{
    while (USART_GetFlagStatus(USART1, USART_FLAG_TXE) == RESET)
    {
        /* 避免覆盖上一份尚未被串口取走的数据。 */
    }
    USART_SendData(USART1, data);
}

/**
 * @brief  发送以零字符结尾的字符串，不发送结尾零字符
 * @param  text：指向有效字符串的指针，不得为空指针
 * @retval 无
 */
void Serial_SendString(const char *text)
{
    while (*text != '\0')
    {
        Serial_SendByte((uint8_t)*text);
        text++;
    }
}

/**
 * @brief  为本章MicroLIB配置提供标准输出的字符发送入口
 * @param  ch：标准输出提供的字符
 * @param  stream：标准库传入的流，本章统一发往USART1
 * @retval 已提交的字符
 */
int fputc(int ch, FILE *stream)
{
    (void)stream; /* 本章只有一个输出目的地，无需区分流。 */
    Serial_SendByte((uint8_t)ch);
    return ch;
}

/**
 * @brief  格式化输出，供后续章节统一调用
 * @param  format：格式字符串；后续参数须与格式符匹配
 * @retval 无
 */
void Serial_Printf(const char *format, ...)
{
    va_list args;

    /* 把可变参数交给标准库处理，避免自行拼接数值字符串。 */
    va_start(args, format);
    vprintf(format, args);
    va_end(args);
}
```

##### 6.6.3 `User/main.c`

```c
#include "stm32f10x.h"
#include "Delay.h"
#include "Serial.h"
#include <stdio.h>

/**
 * @brief  演示字符、字符串和整数的串口发送
 * @param  无
 * @retval 正常运行时不返回
 */
int main(void)
{
    uint32_t count = 0;

    Serial_Init(); /* 任何发送操作都必须在初始化之后执行。 */

    Serial_SendByte('A');
    Serial_SendString("\r\n");
    Serial_SendString("Hello, STM32!\r\n");
    printf("printf: ready\r\n");
    Serial_Printf("boot: serial ready\r\n");

    while (1)
    {
        Serial_Printf("count=%lu\r\n", (unsigned long)count);
        count++;
        Delay_ms(1000); /* 降低输出频率，方便观察，不用于精密计时。 */
    }
}
```

接口使用约定：`Serial_Init` 在启动时调用一次；发送函数用于主循环中的少量调试输出。后续中断章节应在中断中记录状态，再由主循环打印；本章不保证多处同时打印时的并发安全性。

| 预期现象 | 验证方法 |
|---|---|

**常见错误对照表**

| 问题 | 优先检查什么 | 如何处理 |
|---|---|---|
| 设备管理器没有任何新端口 | USB 线是否只支持充电、ST-Link 驱动、USB 接口 | 换一根支持数据传输的线并换口试；回到第 2 章重装 ST-Link 驱动 |
| 能下载程序，但没有虚拟串口 | ST-Link 固件是否开启虚拟串口 | 联系负责人确认固件，不要自行刷写 |
| 端口打开失败 | 是否被其他软件占用（VOFA+ 连接后，其他串口软件不能再打开同一端口） | 关闭其他串口助手或终端，回到 VOFA+ 重新连接 |
| 端口正常但没有输出 | 是否选中板载 ST-Link 虚拟串口、程序是否下载成功、是否按过复位 | 先连接串口再按一次复位键；重新下载一次工程 |
| 出现乱码 | 两端参数、控制台编码 | 统一9600、8位、1位停止、无校验、无流控；控制台编码在 `UTF-8` 与 `GBK` 间切换试试；再核对模板主频配置 |
| 显示一串 `48 65 ...` | 控制台是否处于 `Hex` 十六进制模式 | 点击控制台工具栏的 `Abc` 按钮，切回文本模式 |
| 只有计数，没有欢迎信息 | 是否在启动输出之后才连接串口 | 保持串口连接，按复位键 |
| 字符串正常，`printf` 不正常 | MicroLIB、编译器、重定向实现 | 按本章配置核对；工程只能保留一份 `fputc` 实现 |
| 提示 `Serial_Init` 等未定义 | `Serial.c` 是否加入工程 | 文件复制到文件夹后，还要加入 Keil 分组 |
| 提示 `USART_Init` 等未定义 | 模板是否包含USART标准库源文件 | 交由负责人补齐公共模板，不手写库函数替代 |
| 提示找不到 `Serial.h` 或 `Delay.h` | 文件位置、头文件搜索路径 | 对照6.2和6.5.1，沿用模板的延时模块 |
| 启动提示反复出现，计数总回到0 | 是否持续复位、供电不稳 | 先检查复位键、USB 连接和下载调试状态 |

遇到问题时，按“电脑能否识别 ST-Link → 有没有虚拟串口 COM 端口 → 端口能否打开 → 能否收到字符 → 格式化打印是否正常”的顺序排查，每次只改变一个条件。

#### 6.8 小练习

1. 把欢迎信息改成自己的英文名字或学号。验收：复位后显示正确，没有影响后续计数。
2. 将输出改为 `loop=0, state=running` 这样的格式，并让数字持续增加。提示：改变格式字符串，保留与数值类型匹配的格式符。
3. 把一次启动提示移动到 `while (1)` 内，观察输出次数的变化，再解释循环外和循环内的差别。

选做：把发送端与串口助手的波特率都改为 `115200`，验证仍能正确显示。修改后若出现乱码，先检查是否只改了一端。
